Contributing

How to Contribute to PRISMS-PF

Thank you for taking an interest in contributing to PRISMS-PF! These are some notes that may be useful for contributors. Feel free to expand this document if you think there is anything else that should be known. We will assume you already have a working knowledge of git and GitHub. If you are new to git, we recommend checking out the GitHub Docs

Formatting Rules

PRISMS-PF has rules for text formatting. We format with clang-format. We recommend using an autoformatter with your developing environment. If you are using VSCode, installing the Clang-Format extension and turning on format on save in settings may be useful. You will also need a clang-format installation from your cli.

To ensure that your commits will pass our requirements before your pull-request, you can run pre-commit inside the repo, which will format the code properly and catch spelling errors. Your changes may need to be staged first if new files are added.

# One-time installation:
python3 -m pip install pre_commit
# From any directory in the repo:
python3 -m pre_commit run --all-files
# Repeat until all-passing

Adding an application

You can start to create a new application by copying an existing one. There are a couple of things you should make sure to do though. First, make sure to rename the project in the new application's CMakeLists.txt.

# ...
# Name the application
set(APPLICATION_NAME "my_app_name")
# ...

The other step is to add the relative path to your new application directory to the list at the top of applications/CMakeLists.txt.

set(
# ...
coupled_allen_cahn_cahn_hilliard
mechanics/boundary_value_problem
mechanics/eshelby_inclusion
my_app_directory
# ...
)

Documentation

This section explains how to preview changes to documentation locally.There are a few components of our documentation:

  • Doxygen-style inline code documentation (core library and applications)
  • Doxygen-style manual documentation
  • GitHub pages website

Both the inline code documentation and manual documentation are bundled together in what we call the PRISMS-PF User Manual. As a developer (and user) this is what you'll be using and changing the most. To visualize the User Manual locally you'll need Doxygen and Graphviz. On Ubuntu these can be installed with

sudo apt-get install doxygen graphviz

Additionally, we use Doxygen Awesome as a submodule to make everything look pretty. The submodules can be downloaded with

git submodule update --init --recursive
Warning
If you don't have Doxygen Awesome the website will not render correctly.

With all the prerequisites, we just need to build the documentation. Newer versions of CMake can use the CMakePresets.json

cmake --workflow --preset docs

or without the preset

cmake -DPRISMS_PF_DOCS=ON -DCMAKE_BUILD_TYPE=Debug -B build
cmake --build build --target doc -j <nprocs>

Once the build is complete you can visualize the local documentation by navigating to the doxygen folder in the build directory and starting a python HTTP server.

cd build/docs/doc/contrib
python3 -m http.server 8000

You can open the http://localhost:8000/ on whatever web browser you use.

Note
Some features of the User Manual don't render locally (e.g., the version selector).
